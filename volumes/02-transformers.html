The Sequence Modelling Problem

Every Transformer design decision is an answer to a failure of what came before. This chapter states those failures precisely, so that attention arrives as the obvious fix rather than as a recipe.

The Engineering Problem

We need a function that maps a sequence of T vectors to T vectors, where each output may depend on any input. It must train in parallel on accelerators, pass gradients across hundreds of thousands of positions, and not compress the whole history into a fixed-size bottleneck.

Why Recurrent Networks Bottleneck

An RNN computes h_t = \tanh(W h_{t-1} + U x_t). Three problems follow directly from that equation.

  • Sequential compute. h_t needs h_{t-1}. Training on a sequence of length T takes T dependent steps, so a GPU with 10,000 cores does one small matmul at a time. Critical path length is O(T).
  • Vanishing and exploding gradients. \partial h_T / \partial h_0 = \prod_t \operatorname{diag}(1 - h_t^2) W. A product of T Jacobians shrinks or grows geometrically. LSTMs and GRUs add gated additive paths that slow the decay; they do not remove it.
  • Fixed-size state. Everything the model knows about the prefix must fit in one vector h_t \in \mathbb{R}^d. For seq2seq translation, the entire source sentence was squeezed into a single vector before decoding began.
T=  1  ||dh_T/dh_0|| = 1.49e+00
T= 10  ||dh_T/dh_0|| = 1.93e-02
T= 25  ||dh_T/dh_0|| = 4.62e-06
T= 50  ||dh_T/dh_0|| = 6.12e-12
T=100  ||dh_T/dh_0|| = 5.14e-24
  • After 25 steps the signal from the first token is attenuated by a factor of about 10^{-6}; after 100 steps it is below float32 resolution. The model cannot learn a dependency it receives no gradient for.
  • Scaling W up to spectral radius above 1 flips the problem to explosion. There is no stable middle ground for a plain RNN over long spans.

Attention as Differentiable Lookup

A hash map returns the value whose key equals the query. Attention returns a weighted average of all values, weighted by how similar each key is to the query. Because the weights come from a softmax, the lookup is differentiable end to end.

\operatorname{lookup}(q) = \sum_{j} \operatorname{softmax}_j\big(\operatorname{sim}(q, k_j)\big)\, v_j
  • Bahdanau (2014): decoder state is the query, encoder states are keys and values, similarity is a small MLP (additive attention). This removed the seq2seq bottleneck: the decoder can look back at every source position.
  • Luong (2015): similarity becomes a dot product, which is a single matmul on hardware.
  • Self-attention (Vaswani et al. 2017): queries, keys and values all come from the same sequence, via learned linear projections. Remove the recurrence entirely; stack attention with per-token MLPs.
Key Idea
  • Self-attention gives every pair of positions a direct, one-step connection. Gradient path length between any two tokens is constant, not O(T).
  • All T outputs are computed with a few large matmuls, so training is parallel across the sequence.
  • The price is O(T^2) pairwise scores. Volumes 7 and 11 are largely about paying that price more cheaply.

Tensor Mechanics for Attention

Attention bugs are almost never conceptual. They are a transpose on the wrong axes, a reshape of a non-contiguous tensor, or an overflow in exp. This chapter fixes the tensor vocabulary and builds the one numerical primitive attention depends on: a stable softmax.

Views, Strides and Copies

  • An array is a pointer, a shape and strides (bytes to step along each axis). reshape of a contiguous array and transpose only rewrite shape and strides; no data moves.
  • After a transpose, the memory is no longer laid out in row-major order. A subsequent reshape that merges the transposed axes must copy. In PyTorch, view refuses and raises; reshape silently copies; .contiguous() makes the copy explicit.
  • Multi-head attention does exactly this twice per layer: split heads (reshape then transpose) and merge heads (transpose then reshape). The merge is a real memory copy on the hot path, which is why fused kernels avoid it.

contiguous?     : False

Batched matmul and einsum

  • @ broadcasts over all leading axes and contracts the last axis of the left operand with the second-to-last of the right. q @ k.swapaxes(-1, -2) is the attention score for every batch and head at once.
  • einsum("bhtd,bhsd->bhts", q, k) states the contraction explicitly. Prefer it in reference code: the index string is the documentation. Production code often uses @ because some backends dispatch it more predictably.

Numerically Stable Softmax

\operatorname{softmax}(x)_i = \frac{e^{x_i}}{\sum_j e^{x_j}} = \frac{e^{x_i - m}}{\sum_j e^{x_j - m}}, \quad m = \max_j x_j
  • Shift invariance: multiplying numerator and denominator by e^{-m} changes nothing mathematically.
  • Overflow: with m subtracted, the largest exponent is e^0 = 1, so nothing overflows. float32 overflows at e^{88.7}; float16 at e^{11.1}. Attention logits routinely exceed 11.
  • Underflow: small probabilities underflow to 0, and log(0) = -inf. Compute \log\operatorname{softmax}(x)_i = x_i - m - \log\sum_j e^{x_j - m} directly (log-sum-exp). Cross-entropy must always use this form.
  • Fully masked rows: if every entry is -inf, then m = -\infty and x - m is nan. The implementation below guards against it; Chapter 4 explains when it happens.

Failure Mode
  • np.log(softmax(x)) returned -inf for a logit of −1000; log_softmax returned the correct −1005. A single -inf in a loss becomes nan gradients and a dead training run.
  • Framework functions (F.cross_entropy, F.log_softmax) are stable. Hand-written losses in custom training code are the usual culprit.

Scaled Dot-Product Attention from Scratch

Scaled dot-product attention (SDPA) is five lines of code. This chapter derives each line, proves the scale factor is necessary, checks the gradients numerically, and matches PyTorch to machine precision.

Q, K and V as Learned Projections

Given token representations X \in \mathbb{R}^{T \times C}:

Q = X W_Q,\quad K = X W_K,\quad V = X W_V,\qquad W_Q, W_K \in \mathbb{R}^{C \times d_k},\ W_V \in \mathbb{R}^{C \times d_v}
\operatorname{Attention}(Q, K, V) = \operatorname{softmax}\!\left(\frac{Q K^\top}{\sqrt{d_k}}\right) V
  • Query: what this position is looking for. Key: what this position offers to be matched on. Value: what this position hands over if matched.
  • Separate projections matter. With Q = K, the score matrix is symmetric and every token attends most strongly to itself; separate projections let "looking for a subject" differ from "being a subject".
  • QK^\top \in \mathbb{R}^{T \times S}: row i holds token i's scores against every key. Softmax is taken over keys (the last axis), so each row is a probability distribution.

Why Scale by the Square Root of d_k

Without scaling, attention collapses to near one-hot as the head dimension grows, and softmax gradients vanish. Training stalls, and the effect gets worse precisely in wider models.

Assume the components of q and k are independent with mean 0 and variance 1 (roughly what normalisation and initialisation give you). Then

\operatorname{Var}(q \cdot k) = \sum_{i=1}^{d_k} \operatorname{Var}(q_i k_i) = \sum_{i=1}^{d_k} \mathbb{E}[q_i^2]\,\mathbb{E}[k_i^2] = d_k
  • The standard deviation of a raw score is \sqrt{d_k}: 8 for d_k = 64, 32 for d_k = 1024. Softmax of logits spread that widely is nearly one-hot.
  • The softmax Jacobian is \operatorname{diag}(p) - pp^\top. When p is one-hot, every entry is 0: no gradient flows to the scores, so W_Q and W_K stop learning.
  • Dividing by \sqrt{d_k} restores unit variance regardless of width. It is a fixed temperature chosen so the initial distribution is soft.
 d_k   var(q.k)  var(q.k/sqrt(d_k))  max softmax weight (T=64)
   16      15.5        0.969      raw=0.550 scaled=0.100

  256     251.8        0.984      raw=0.902 scaled=0.110

  • Measured variance tracks d_k closely; after scaling it stays at about 1 for every width.
  • Unscaled, the average maximum attention weight over 64 keys rises from 0.55 to 0.93 as d_k grows: attention is already nearly hard at initialisation. Scaled, it stays near 0.1 regardless of width.
Beyond the Fixed Scale
  • The argument holds only at initialisation. During training, query and key norms can grow, producing attention logit growth and loss spikes in large models.
  • Fixes used in practice: QK-norm (normalise q and k per head before the dot product), logit soft-capping (c \tanh(s/c), used in Gemma 2), and a learned temperature. Volume 6 covers training stability.

How it works

  • Scores: one batched matmul, O(T S d_k) FLOPs.
  • Mask: replace forbidden scores with -\infty so that e^{-\infty} = 0 exactly.
  • Softmax over keys, then a second matmul O(T S d_v) to mix values.
  • Memory: the T \times S weight matrix is materialised. At T = S = 32{,}768, 32 heads and fp16 that is 64 GiB per layer per sequence. FlashAttention (Chapter 11, Volume 11) never materialises it.

Gradients and a Numerical Check

With S = QK^\top/\sqrt{d_k}, P = \operatorname{softmax}(S), O = PV and upstream gradient G = \partial L/\partial O:

dV = P^\top G,\quad dP = G V^\top,\quad dS = P \odot \big(dP - \operatorname{rowsum}(dP \odot P)\big),\quad dQ = \frac{dS\,K}{\sqrt{d_k}},\quad dK = \frac{dS^\top Q}{\sqrt{d_k}}
  • The dS line is the softmax Jacobian-vector product applied row by row, without ever forming the T \times T \times T Jacobian.
  • This is exactly the backward pass FlashAttention recomputes tile by tile; the rowsum(dP ⊙ P) term is its D vector.

Relative errors around 10^{-9} to 10^{-10} are what central differences with \epsilon = 10^{-6} achieve in float64. A wrong transpose or a missing scale would give errors of order 1.

Testing Pattern
  • Keep one slow, obviously correct reference (NumPy, float64) and test every fast implementation against it with a tolerance chosen for the dtype: about 10^{-12} in float64, 10^{-5} in float32, 10^{-2} in bf16.
  • Test gradients as well as outputs. A forward pass can be right while a custom backward is wrong.

Masking

Masks encode two different facts: "this position is in the future" and "this position is not real". Getting either wrong produces a model that trains beautifully and fails in production.

The Engineering Problem

  • Causality: a language model trained with teacher forcing sees the whole sequence at once. Without a mask, position t can read token t+1 (the answer), training loss goes to near zero, and generation is garbage.
  • Padding: batches contain sequences of different lengths padded to a common S. Real tokens must not attend to padding, or outputs depend on how much padding the batch happened to have.

Causal, Padding and Combined Masks

  • Causal: lower-triangular T \times S, allowing key j for query i iff j \le i + (S - T). The offset matters when queries are a suffix of keys, as in KV-cached decoding.
  • Padding: per-sequence (B, S) key mask, broadcast over queries.
  • Combined: logical AND, broadcast to (B, 1, T, S) or (B, H, T, S).
  • Additive form: many kernels take a float mask added to scores (0 to keep, -\infty to block). Boolean conventions also differ: our sdpa and F.scaled_dot_product_attention use True = attend; nn.MultiheadAttention uses True = block. the nn.MultiheadAttention parity check in Chapter 5 inverts accordingly.

  • Rows 3 and 4 of the second sequence are padding queries. They still produce outputs (attending to real tokens), which is harmless provided the loss ignores them (ignore_index in cross-entropy).
  • With left padding and a causal mask, the first real query can see only padding keys, giving an all--inf row. That is why softmax guards the max and sdpa calls nan_to_num.

−inf Versus a Large Negative Number

-inf

  • Masked weights are exactly 0; no leakage at any logit scale.
  • Fully masked rows produce nan unless handled explicitly.

Large negative (−1e9, or dtype minimum)

  • Fully masked rows become uniform instead of nan; no special case.
  • −1e9 overflows in fp16 (max 65,504) to -inf anyway; use torch.finfo(dtype).min.
  • Adding a mask of dtype minimum to a large negative score can overflow to -inf; subtle, dtype-dependent bugs.

Failure Mode: Leakage from the Future, and a Test That Catches It

The property to test is behavioural, not structural: perturbing token t must not change any output at positions before t. It catches transposed masks, off-by-one masks, a mask applied after softmax, and future information leaking through non-attention paths (for example a normalisation over the time axis).

correct mask : ok: no future information reaches the past
transposed   : LEAK: position 1 changed earlier outputs by 6.63e-02
no mask      : LEAK: position 1 changed earlier outputs by 6.63e-02
  • Transposed mask (triu instead of tril): each token sees only the future. Training loss collapses; the leakage test fails at position 1.
  • Off by one (k=1 in tril): each token sees exactly one future token. Loss looks excellent; generation is incoherent.
  • Mask after softmax: weights no longer sum to 1, and gradients still flow through the softmax denominator from future keys.
  • Padding side mismatch: training with right padding and serving with left padding changes positions and masks; outputs drift.
Put It in CI

Run leak_test on every model class, not just the attention function. It runs in milliseconds and is the cheapest insurance in this volume. Chapter 9 applies it to a full block.

Multi-Head Attention

One attention distribution per token can express only one "kind" of relationship at a time. Multi-head attention runs several smaller attentions in parallel on different learned subspaces, for the same parameter and FLOP budget.

Splitting and Merging Heads

\operatorname{MHA}(X) = \operatorname{Concat}(\text{head}_1, \ldots, \text{head}_H)\, W_O,\qquad \text{head}_h = \operatorname{Attention}(X W_Q^{(h)}, X W_K^{(h)}, X W_V^{(h)})
  • Each head has width D = C/H. Instead of H separate matmuls, project once to C and reshape (B, T, C) \to (B, T, H, D) \to (B, H, T, D).
  • Q, K and V projections are fused into one C \times 3C matmul: one large GEMM is faster than three small ones.
  • W_O mixes information across heads. Without it, head outputs would stay in disjoint channel slices of the residual stream.

What Heads Learn, and Redundancy

  • Documented Heads specialise: previous-token heads, heads tracking syntactic dependencies, and induction heads that complete repeated patterns (Clark et al. 2019; Olsson et al. 2022).
  • Documented Many heads are redundant at inference: Michel et al. (2019) pruned a large fraction of heads with little loss, and Voita et al. (2019) found a few specialised heads do most of the work.
  • Redundancy is an inference-cost opportunity. Multi-query attention (MQA) and grouped-query attention (GQA) share K and V across heads to shrink the KV cache, with small quality loss (Volume 7).

Position Information

Attention is a function of a set. "Dog bites man" and "man bites dog" produce the same outputs, merely permuted. Order has to be injected, and how it is injected determines how a model behaves beyond its training length.

Permutation Equivariance, Demonstrated

For any permutation matrix P, \operatorname{MHA}(PX) = P\,\operatorname{MHA}(X) when there is no mask and no position signal.

permutation perm: [5 1 0 2 4 3]
attention(P x) == P attention(x): True

The causal mask does break the symmetry partially (position t sees t tokens), and causal models without any positional encoding (NoPE) can learn some position information from that. It is weak and not relied upon in practice.

Sinusoidal Encoding

PE_{p,2i} = \sin\!\big(p\,\theta_i\big),\quad PE_{p,2i+1} = \cos\!\big(p\,\theta_i\big),\quad \theta_i = 10000^{-2i/C}
  • Each pair of channels is a clock at a different frequency, from period 2\pi to 2\pi \cdot 10000.
  • PE_{p+k} is a fixed rotation of PE_p, so PE_p \cdot PE_{p+k} depends only on k. But the encoding is added to content, so content–position cross-terms pollute the score and relative structure is not guaranteed after projection.

ALiBi

s_{ij} = \frac{q_i \cdot k_j}{\sqrt{d_k}} - m_h \,(i - j),\qquad m_h = 2^{-8h/H}
  • No embedding at all: a per-head linear penalty on distance, with geometric slopes so some heads are local and some near-global.
  • Extrapolates in perplexity because the bias for unseen distances is just a larger penalty. It does so partly by ignoring distant tokens, which hurts long-range retrieval tasks.

Relative Bias (T5)

  • Instead of adding a position vector to embeddings, T5 adds a learned scalar bias to each attention score that depends on the clipped relative offset i - j (Raffel et al. 2019).
  • Offsets beyond a few buckets share one bias, so the table stays small and can generalise past the training length better than learned absolute embeddings.
  • Unlike RoPE, the bias is not content-dependent: it cannot express "attend relatively when the tokens match". That is why most modern LLMs prefer RoPE (or ALiBi) over T5-style relative bias for decoder-only models.

RoPE: Rotary Position Embedding

Derivation

We want a transform f(x, m) applied to queries and keys such that the score depends on content and relative position only: \langle f(q, m), f(k, n)\rangle = g(q, k, m - n). Treat each channel pair as a complex number z = x_{2i} + i\,x_{2i+1} and rotate it by an angle proportional to position:

f(z, m) = z\, e^{i m \theta_i} \quad\Rightarrow\quad \operatorname{Re}\!\big[f(q, m)\,\overline{f(k, n)}\big] = \operatorname{Re}\!\big[q\,\bar{k}\, e^{i (m-n)\theta_i}\big]
  • The absolute positions cancel; only m - n survives. Summing over pairs gives the real dot product.
  • In real arithmetic each pair is multiplied by a 2 \times 2 rotation matrix \begin{pmatrix}\cos m\theta_i & -\sin m\theta_i \\ \sin m\theta_i & \cos m\theta_i\end{pmatrix}. Rotations preserve norms, so RoPE does not change the variance argument of Chapter 3.
  • RoPE is applied to q and k only, never to v: position shapes where to look, not what is retrieved.
  • Low-index pairs rotate fast (local position); high-index pairs rotate slowly (coarse position). Long-context methods (position interpolation, NTK scaling, YaRN) rescale these frequencies.

Interleaved Versus Half-Split Layout

We rotate adjacent pairs (x_0, x_1), (x_2, x_3), \ldots as in the RoFormer paper and Meta's original Llama code. Hugging Face Llama uses rotate_half, pairing x_i with x_{i + D/2}. Both are valid; they are not interchangeable. Loading weights trained with one layout into code using the other silently degrades the model; conversion scripts permute the Q and K projection rows to compensate.

Length Extrapolation Behaviour

  • Learned absolute: hard wall at T_{\max}.
  • Sinusoidal: defined everywhere, but the model has never seen those phase combinations; perplexity rises quickly.
  • RoPE, unmodified: low-frequency pairs reach angles never seen in training; attention scores go out of distribution and perplexity explodes a little past the training length.
  • RoPE plus interpolation or YaRN: rescale positions or frequencies so that angles stay in the trained range, then fine-tune briefly. This is how most models extend from 4k–8k to 128k context (Volume 7).
  • ALiBi: stable perplexity well past training length, but effective use of distant context is limited.

Feed-Forward Networks and Gating

Attention moves information between positions. The feed-forward network (FFN) transforms information within a position. It holds about two-thirds of the parameters of a typical LLM, and is where much factual association is stored.

The Per-Token MLP

\operatorname{FFN}(x) = \phi(x W_1)\, W_2,\qquad W_1 \in \mathbb{R}^{C \times 4C},\ W_2 \in \mathbb{R}^{4C \times C}
  • Applied independently to every token: it is a 1 \times 1 convolution over the sequence. No information crosses positions.
  • Expansion ratio 4 is convention from the original paper, not a law. It sets FFN parameters at 8C^2 versus 4C^2 for attention.
  • GELU, x\,\Phi(x), is a smooth ReLU: non-zero gradient for small negative inputs, which avoids dead units. GPT-2 uses a tanh approximation; PyTorch supports both via approximate=.

GLU Variants and SwiGLU

\operatorname{SwiGLU}(x) = \big(\operatorname{SiLU}(x W_{\text{gate}}) \odot x W_{\text{up}}\big)\, W_{\text{down}},\qquad \operatorname{SiLU}(z) = z\,\sigma(z)
  • One branch computes features, the other computes a data-dependent gate. Multiplicative interactions let a single layer express functions a plain MLP needs more width for.
  • Three matrices instead of two. To compare fairly at equal parameters, shrink the hidden width to \tfrac{2}{3} \cdot 4C = \tfrac{8}{3}C, usually rounded up to a hardware-friendly multiple.
  • Documented Shazeer (2020) found GEGLU and SwiGLU gave the best perplexity among variants at matched parameters and compute. The paper famously offers no explanation, attributing success to "divine benevolence".

SwiGLU

  • Better quality per parameter; the default in Llama, Mistral, Qwen, Gemma (GeGLU).
  • Hidden size sits at awkward values; three GEMMs instead of two, though gate and up can be fused.

GELU MLP

  • Simpler, two GEMMs, slightly faster per parameter.
  • Measurably worse perplexity at the same budget.

Residuals and Normalisation

A deep Transformer is trainable because of two components that do no "modelling" at all: residual connections and normalisation. Where the normalisation sits decides whether a 100-layer model trains out of the box or needs careful warm-up.

The Residual Stream View

  • Write the block as x_{l+1} = x_l + \operatorname{Attn}(x_l) + \operatorname{FFN}(\ldots). The running sum x is the residual stream: a shared communication channel of width C.
  • Every layer reads from the stream (via a projection) and writes an additive update to it. The final logits are a linear readout of the sum of all updates plus the embedding.
  • Gradient of the loss with respect to x_l contains an identity term through every residual, so gradients reach early layers undiminished (He et al. 2015). This is the Transformer's answer to Chapter 1's vanishing gradient.
  • The stream view underpins mechanistic interpretability (Elhage et al. 2021): heads and MLPs are independent readers and writers that can be analysed separately.

Post-LN Versus Pre-LN

  • Post-LN: normalisation on the residual path rescales gradients at every layer. Xiong et al. (2020) show gradient norms near the output are large at initialisation, so post-LN needs learning-rate warm-up and still diverges in deep stacks.
  • Pre-LN: the identity path is clean; training is stable without careful warm-up. Cost: the stream's norm grows with depth, so later layers' updates are relatively smaller, and a final norm before the head is mandatory.
  • Documented Post-LN often reaches slightly better final quality when it trains at all; variants such as DeepNorm and sandwich norm try to have both.

LayerNorm Versus RMSNorm

\operatorname{LN}(x) = \gamma \odot \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta,\qquad \operatorname{RMSNorm}(x) = \gamma \odot \frac{x}{\sqrt{\tfrac{1}{C}\sum_i x_i^2 + \epsilon}}
  • RMSNorm drops mean-centring and the bias. Zhang and Sennrich (2019) found re-centring contributes little; removing it saves one reduction per token, which matters because normalisation is memory-bound.
  • Both normalise over the channel axis per token, never over the batch or time axis. Normalising over time would leak future information through the statistics.

Initialisation and Stability

  • Each block adds two updates to the stream. With L layers the stream variance grows roughly as 1 + 2L\sigma^2_{\text{update}}.
  • GPT-2 scales the init of the output projections (W_O, W_{\text{down}}) by 1/\sqrt{2L} so the stream stays O(1) at initialisation; our block in Chapter 9 does the same.
  • Norm gains initialised to 1; embeddings with small standard deviation (0.02 is the GPT-2 convention).
  • Symptoms of bad initialisation: loss spikes in the first few hundred steps, activations growing layer by layer, a few channels with huge magnitudes (outlier features), which later break int8 quantisation (Volume 11).
Why the Final Norm Matters

In pre-LN models the last block's output is unnormalised and its scale grows with depth. Without the final norm before the unembedding, logit scale depends on depth and the softmax temperature is effectively uncontrolled.

Cross-Attention

  • Queries from the decoder stream; keys and values from the final encoder output: \operatorname{Attention}(X_{\text{dec}} W_Q,\ X_{\text{enc}} W_K,\ X_{\text{enc}} W_V). Our sdpa already supports it because T \ne S is allowed.
  • No causal mask (the whole source is known), but a padding mask on the source.
  • Encoder K and V are computed once per input and reused at every decoding step, a natural cache.
  • The same mechanism conditions image generators on text (Volume 20) and connects vision encoders to LMs in some multimodal designs (Volume 19).

Why Decoder-Only Won for LLMs

  • One objective, every token supervised. Next-token prediction on raw text gives a loss at every position; BERT's masked LM supervises about 15%.
  • Tasks become text. Instructions, examples and answers all fit into one stream, enabling in-context learning and a single model for everything.
  • Simple scaling and serving. One stack, one mask, one KV cache. Encoder-decoder needs two stacks and a policy for splitting inputs and outputs.
  • Documented Wang et al. (2022) found encoder-decoder with MLM-style objectives is stronger after multitask fine-tuning, but causal decoder-only is best at zero-shot generalisation after pretraining alone, which is the property that matters for general assistants.
  • Inferred Ecosystem lock-in (tooling, kernels, serving engines optimised for decoder-only) now reinforces the choice independently of modelling merits.

Causal Language Modelling

A stack of blocks becomes a language model with an embedding, a final norm, an unembedding and one loss. This chapter trains one end to end to prove the whole stack works.

The Objective

\mathcal{L} = -\frac{1}{T}\sum_{t=1}^{T} \log p_\theta(x_t \mid x_{<t}),\qquad \text{PPL} = e^{\mathcal{L}}
  • Teacher forcing: during training the model conditions on the true prefix, not its own samples. With a causal mask, one forward pass yields all T predictions in parallel.
  • Shifted targets: inputs are seq[:, :-1], targets are seq[:, 1:]. Position t predicts token t+1. Forgetting the shift trains an identity function: loss goes to 0 and nothing is learned.
  • Units: with natural log the loss is in nats; divide by \ln 2 for bits. Bits per byte (loss in bits × tokens / bytes) compares models across tokenisers; perplexity does not.
  • Exposure bias: at inference the model conditions on its own outputs, a distribution it never trained on. Errors can compound; in practice scale and data make this manageable.

What the Model Learned: Attention Patterns

Reversal has a known algorithm: output position t must copy the token at source position 2N - 1 - t. We can check whether some head attends there.

query  8 -> source 7: best layer 0 head 3 weight 0.99
query  9 -> source 6: best layer 1 head 1 weight 1.00
query 10 -> source 5: best layer 0 head 2 weight 0.00
query 11 -> source 4: best layer 0 head 0 weight 0.00
query 12 -> source 3: best layer 1 head 3 weight 0.99
query 13 -> source 2: best layer 1 head 1 weight 1.00
query 14 -> source 1: best layer 0 head 0 weight 0.01
query 15 -> source 0: best layer 1 head 2 weight 1.00
  • For five of eight positions one head puts essentially all its weight on the correct source token: a learned, content-independent, position-addressed copy.
  • For the other three, no head attends directly to the source. The model routes in two hops: a layer-0 head moves the token into another position's residual stream, and a layer-1 head reads it from there. This is the composition of heads that Elhage et al. (2021) formalise, and a reminder that attention maps are evidence, not explanations.
  • Loss drops to 0 in a few steps: targets not shifted, or causal mask missing.
  • Loss stuck at \ln V: learning rate far too high or too low, or gradients not reaching parameters (weight tying broken, no_grad left on).
  • Training loss good, generation bad: train/inference mismatch in masks, positions or padding side.
  • nan after some steps: hand-written log-softmax, fp16 overflow in scores, or a fully masked row.

Production Transformers in PyTorch

Production code computes the same function as our NumPy block. The differences are all about memory traffic, fused kernels and compile-time specialisation. This chapter maps those abstractions back onto what you built.

F.scaled_dot_product_attention and Its Backends

  • One call, F.scaled_dot_product_attention(q, k, v, attn_mask=None, dropout_p=0.0, is_causal=False, scale=None, enable_gqa=False), dispatches to one of several backends based on device, dtype, shapes and mask.
  • FlashAttention-2 (CUDA, fp16/bf16): tiles Q, K and V through on-chip SRAM with an online softmax; never materialises the T \times S matrix. Memory O(T); typically several times faster.
  • Memory-efficient (xFormers-style): similar tiling; supports more dtypes and arbitrary masks.
  • cuDNN attention on recent NVIDIA GPUs.
  • Math: the reference implementation, equivalent to our sdpa. Used on CPU or when no fused kernel supports the inputs.
  • Pass is_causal=True rather than a dense causal mask: a dense mask can disable the Flash backend and costs O(T^2) memory to build.
  • Force or restrict a backend for debugging with torch.nn.attention.sdpa_kernel([SDPBackend.MATH]); compare outputs across backends at bf16 tolerances.

The Online Softmax in One Paragraph

Process keys in blocks. Keep, per query, a running maximum m, running denominator \ell and running output o. For a new block with scores s: m' = \max(m, \max s), \ell' = e^{m - m'}\ell + \sum e^{s - m'}, o' = e^{m - m'} o + e^{s - m'} V_{\text{block}}. Divide by \ell at the end. This is the stable softmax of Chapter 2, made streaming. Volume 11 implements it.

torch.compile

  • Traces the Python model into a graph (TorchDynamo) and generates fused kernels (TorchInductor, Triton on GPU). Norms, activations, RoPE and residual adds fuse into fewer memory-bound kernels.
  • Gains are largest for the memory-bound elementwise ops around attention; matmuls and SDPA are already library kernels.
  • Costs: compile time on first call, recompiles on new shapes (use dynamic=True or pad to buckets), and graph breaks on data-dependent Python control flow.
  • Always check parity between eager and compiled models; numerical differences at bf16 tolerance are expected, larger ones are bugs.

The Mechanistic View

  • Residual stream: a shared bus. Attention heads move information between positions; MLPs transform it in place (Chapter 8).
  • Attention patterns: the P matrix per head. Useful for diagnosis (Chapter 10), but misleading alone, because values and W_O decide what is actually written.
  • Induction heads (Olsson et al. 2022): a two-head circuit. A previous-token head in an earlier layer writes "the token before me was A" into each position; an induction head in a later layer looks for positions whose previous token matches the current token and copies what followed. Pattern [A][B] … [A] → [B].
  • Documented Induction heads form abruptly during training, at the same time as a visible bump in the loss curve and the onset of in-context learning.

The two-hop routing found in Chapter 10 is the same kind of composition on a simpler task. The practical project asks you to train on a repeated-random-sequence task and find a genuine induction head.

Volume Review

What You Learned

  • RNNs fail on long sequences because of sequential compute, geometric gradient decay and a fixed-size state; attention gives O(1) path length and parallel training at O(T^2) cost.
  • Softmax must subtract the max; losses must use log-sum-exp; fully masked rows need an explicit policy.
  • Dot products of unit-variance vectors have variance d_k; dividing by \sqrt{d_k} keeps attention soft and gradients alive.
  • Causal and padding masks encode different facts; the correct test for causality is behavioural (perturb the future).
  • Multi-head attention partitions the same 4C^2 parameters into subspaces; split and merge are reshape plus transpose, and the merge copies.
  • Attention is permutation-equivariant; RoPE injects exact relative position by rotating q and k; extrapolation depends on the scheme.
  • SwiGLU beats a GELU MLP at matched parameters; hidden size \tfrac{8}{3}C.
  • Pre-norm keeps the residual path an identity and trains stably; RMSNorm is LayerNorm without centring.
  • Decoder-only won for LLMs because of dense supervision, tasks-as-text and simple serving.
  • PyTorch modules live in forge.nn and must stay parity-checked against the NumPy reference.

What You Built

  • NumPy reference: stable softmax and log-softmax, SDPA with forward and backward, masks, a leakage test, MHA, sinusoidal PE, RoPE (real and complex), LayerNorm, RMSNorm, GELU and SwiGLU FFNs, and a full Llama-style decoder block.
  • forge.nn: PyTorch modules with a parity suite against NumPy and torch.nn.functional (SDPA, nn.MultiheadAttention, norms, activations, full block), all within 2 \times 10^{-15}.
  • A tiny causal LM on forge.nn that learns sequence reversal to 99.5% exact match in under 20 seconds on CPU.
  • An attention-pattern probe that exposes direct and two-hop copy circuits.

Important Architecture

Failure Modes

  • Naive softmax or log(softmax): overflow, -inf, then nan gradients.
  • Missing \sqrt{d_k} scale: near-hard attention at initialisation and stalled learning.
  • Transposed or off-by-one causal mask: excellent training loss, useless generation.
  • Opposite boolean mask conventions between libraries.
  • Reshape without transpose when splitting heads: runs, wrong.
  • RoPE layout mismatch (interleaved versus half-split) when loading weights.
  • Unshifted targets: the model learns the identity.
  • Post-LN in deep stacks without warm-up: divergence.
  • Padding side differing between training and serving.

Evaluation

  • Component level: parity with a float64 reference, gradient checks, the leakage test.
  • Model level: synthetic tasks with known solutions (copy, reverse, induction) and exact-match accuracy, compared against chance loss.
  • Report loss in nats and bits; use bits per byte to compare across tokenisers.
  • Backends: compare math, Flash and compiled paths at dtype-appropriate tolerances.
