Why Architectures Keep Changing

The 2017 Transformer was designed for training throughput on 512-token translation pairs. Today's models serve millions of users with 128K-token contexts, and most of their lifetime cost is inference. Nearly every architectural change in this volume is an answer to one question: how do we cut the bytes moved per generated token without losing quality?

The Engineering Problem

A 7B model with standard multi-head attention (MHA) serving 32 concurrent users at 32K context needs about 550 GB of KV cache, seven H100s' worth of memory, just to remember the conversation. The weights themselves are 15 GB. The model is not compute-bound, it is not even weight-bound: it is bound by its own memory of past tokens.

The design drivers, in order of current importance

  • Decode bandwidth. Each generated token reads all active weights and the whole KV cache from HBM. Arithmetic intensity is tiny, so tokens per second is set by bytes per step (Volume 1, Chapter 4).
  • KV-cache capacity. Cache size limits batch size, and batch size sets cost per token. It grows linearly with context and with users.
  • Training FLOPs per quality point. Mixture of experts adds parameters without adding FLOPs per token.
  • Context length. Product demand (whole repositories, long documents, agent traces) pushes context from 2K to 128K–1M tokens. Attention is quadratic in prefill and linear per step in decode.
  • Hardware fit. Features that map onto fused kernels (FlashAttention, grouped GEMMs) win; elegant ideas that do not are ignored.

Where the Bytes Go During Decode

The KV-cache size for one sequence is

\text{KV bytes} = 2 \cdot L \cdot n_{kv} \cdot d_h \cdot T \cdot b
  • L layers, n_{kv} key/value heads, d_h head dimension, T tokens, b bytes per element; the 2 counts K and V.
  • Weights are read once per decode step and shared across the batch. The cache is read once per sequence. So the cache share of traffic grows with both batch size and context.

Key Idea
  • Prefill is compute-bound; decode is memory-bound. Architectures are now designed for decode.
  • Three levers reduce decode bytes: fewer KV bytes per token (MQA, GQA, MLA, quantised cache), fewer cached tokens (sliding windows, SSMs), and fewer active weight bytes per token (MoE).
  • Every lever trades something: quality, training stability, communication, or retrieval ability over long ranges.

Multi-Query, Grouped-Query and Multi-Head Latent Attention

The cheapest way to shrink the KV cache is to cache fewer heads. MQA keeps one, GQA keeps a few, and MLA keeps a compressed latent from which all heads are reconstructed. This chapter implements all three, proves they reduce to MHA where they should, and prices them on real model shapes.

The Engineering Problem

In MHA each of H heads caches its own key and value vectors. Queries need per-head diversity to express different attention patterns, but it is not obvious that keys and values do. If several query heads can share one K/V head, the cache shrinks by the sharing factor while the query side keeps its expressiveness.

Possible solutions and what each does not solve

  • Quantise the cache (FP8/INT4 KV): 2–4× saving, orthogonal to the rest, but adds error that grows at long context.
  • MQA (Shazeer, 2019): one shared K/V head. Up to H× saving, measurable quality loss and some training instability.
  • GQA (Ainslie et al., 2023): G K/V heads, each shared by H/G query heads. Interpolates between MHA and MQA; the default since Llama 2 70B.
  • MLA (DeepSeek-AI, 2024, DeepSeek-V2): cache a low-rank latent per token; reconstruct per-head K and V. Cache comparable to small-G GQA with quality reported at or above MHA.
  • None of these reduce prefill FLOPs or quadratic attention cost; they target decode memory.

Implementation Note
  • repeat_interleave materialises the expanded K/V, which costs bandwidth at decode. Production kernels (FlashAttention, FlashInfer, the enable_gqa flag of recent SDPA) index the shared head directly instead.
  • Head ordering matters when loading checkpoints: query head i uses KV head \lfloor i / (H/G) \rfloor. A mismatch between repeat_interleave and repeat silently scrambles groups.
  • With tensor parallelism, G should be divisible by the TP degree, or KV heads get replicated across ranks. This is one reason G = 8 is so common: it matches 8-GPU nodes.

  • MQA loses quality and can be unstable. Ainslie et al. report MQA below MHA on T5-XXL summarisation and translation benchmarks Documented.

Multi-Head Latent Attention

The idea: cache a latent, not the heads

  • GQA shares K/V across heads by a fixed grouping. MLA instead learns a low-rank bottleneck: a per-token latent c^{KV}_t \in \mathbb{R}^{d_c} from which every head's K and V are reconstructed.
  • Only the latent is cached. With d_c \ll 2 H d_h the cache shrinks while each head still gets its own K and V (as a different linear function of the latent).
c^{KV}_t = W^{DKV} h_t, \qquad k^{C}_{t} = W^{UK} c^{KV}_t, \qquad v^{C}_{t} = W^{UV} c^{KV}_t
  • W^{DKV} \in \mathbb{R}^{d_c \times d} is the down-projection; W^{UK}, W^{UV} \in \mathbb{R}^{H d_h \times d_c} are up-projections.
  • Absorption. Because q_{t,i}^\top k_{s,i} = q_{t,i}^\top W^{UK}_i c^{KV}_s = (W^{UK\top}_i q_{t,i})^\top c^{KV}_s, the up-projection can be folded into the query side. At decode you never materialise K; you attend directly over the latents. The same trick folds W^{UV} into the output projection.
  • Decoupled RoPE. RoPE applies a position-dependent rotation between q and k, which breaks absorption (the rotation sits between W^{UK} and the query). DeepSeek-V2 adds a small separate key k^R_t = \mathrm{RoPE}(W^{KR} h_t), shared across heads, of dimension d^R_h = 64, and concatenates it to each head's content key.
  • Cached per token per layer: d_c + d_h^R = 512 + 64 = 576 elements. The report equates this to GQA with 2.25 groups Documented (DeepSeek-AI, 2024).
  • Queries are also low-rank compressed in DeepSeek-V2 (d_c' = 1536) to save activation memory in training; this does not affect the cache.
naive decode vs full   : 5.96e-08
absorbed decode vs full: 5.59e-08
cache per token/layer: MHA 1024 elems, MLA 64 elems -> 16x smaller
  • The absorbed path gives the same output as full attention while touching only the (S, d_c) latent cache: attention over a 64-dim latent instead of 8 × 64-dim heads.
  • Absorption changes the compute shape: every head now does a d_c-dimensional dot product (512 in DeepSeek-V2, versus d_h = 128). Decode becomes more compute-heavy and less bandwidth-heavy, which suits modern GPUs.

Advantages

  • Cache near MQA/small-G GQA with per-head K/V diversity.
  • Reported quality on par with or above MHA at DeepSeek scale.
  • Moves decode from bandwidth-bound towards compute-bound.

Disadvantages

  • Decoupled RoPE adds complexity; naive RoPE breaks absorption.
  • Needs custom kernels (FlashMLA and equivalents) to realise the saving.
  • Cannot be retrofitted cheaply; conversion from GQA requires substantial training.
  • Silent head mis-grouping when loading GQA checkpoints into a different implementation: loss looks plausible but degraded. Test logits against the reference implementation.
  • KV heads not divisible by TP degree: replication wastes memory and complicates sharding.
  • MLA with RoPE applied to the compressed key: absorption no longer holds; decode is either wrong or you fall back to materialising K.
  • Reporting cache savings without quality: an MQA model with 32× less cache and 3 points lower accuracy is not a free win.

Evaluation

  • Measure KV bytes per token (analytic and torch.cuda.max_memory_allocated), maximum batch at fixed context, and tokens per second at that batch.
  • Quality: held-out loss plus long-context retrieval (Chapter 5), because K/V sharing can hurt precise retrieval before it hurts perplexity.

Mixture of Experts

A mixture-of-experts (MoE) layer replaces one dense FFN with many expert FFNs and a router that sends each token to a few of them. Parameters, and therefore knowledge capacity, grow with the number of experts; FLOPs per token grow only with the number chosen. The price is paid in routing instability, load imbalance, memory and communication.

The Engineering Problem

Loss improves with parameters, but in a dense model every parameter is used by every token, so training and inference FLOPs scale with parameter count. We want a model with the capacity of a 670B-parameter network and the per-token compute of a 37B one.

Possible solutions and what each does not solve

  • Bigger dense model: better quality, linear increase in FLOPs and decode bytes.
  • Sparsely-gated MoE (Shazeer et al., 2017): conditional computation per token. Does not reduce memory: all experts must be resident somewhere.
  • Top-1 routing (Fedus et al., 2021, Switch): simplest and cheapest; more sensitive to imbalance.
  • Fine-grained and shared experts (Dai et al., 2024, DeepSeekMoE): more combinatorial flexibility and a dense path for common knowledge; more routing overhead.

How a Top-k Router Works

p(x) = \mathrm{softmax}(W_r x) \in \mathbb{R}^E, \qquad \mathcal{T} = \mathrm{TopK}(p(x), k), \qquad y = \sum_{i \in \mathcal{T}} \frac{p_i(x)}{\sum_{j \in \mathcal{T}} p_j(x)} \, \mathrm{FFN}_i(x)
  • The router is a single linear layer; its output is a probability per expert.
  • The gate weights multiply expert outputs, so the router receives gradient only through the selected experts. Unselected experts get no signal for that token: the source of rich-get-richer collapse.
  • Renormalising over the top-k (Mixtral) versus using raw softmax values (Switch with k=1; DeepSeek-V2) is a design choice; both appear in practice.
  • Shazeer et al. 2017 added tunable Gaussian noise to the logits before top-k (noisy top-k gating) to encourage exploration.

Load balancing: the Switch auxiliary loss

\mathcal{L}_{\text{aux}} = \alpha \cdot E \cdot \sum_{i=1}^{E} f_i \, P_i, \qquad f_i = \frac{1}{N}\sum_{x} \mathbb{1}[\,i \in \mathcal{T}(x)\,], \qquad P_i = \frac{1}{N}\sum_{x} p_i(x)
  • f_i is the fraction of tokens dispatched to expert i (not differentiable); P_i is the mean router probability (differentiable). The product lets gradient push probability away from overloaded experts.
  • The loss equals 1 (before \alpha) under perfectly uniform routing, and grows with imbalance. Switch uses \alpha = 10^{-2} Documented (Fedus et al., 2021).
  • ST-MoE (Zoph et al., 2022) adds a router z-loss, \frac{1}{N}\sum_x (\log \sum_i e^{z_i(x)})^2, which keeps router logits small and was the main stabiliser in their runs.
  • DeepSeek-V3 replaces most of the auxiliary loss with auxiliary-loss-free balancing: a per-expert bias added to the scores for top-k selection only, nudged up or down each step depending on load Documented (DeepSeek-AI, 2024, V3 report).

Capacity factor and token dropping

C = \left\lfloor \mathrm{CF} \cdot \frac{N \cdot k}{E} \right\rfloor
  • Fixed-shape kernels and all-to-all buffers need a static per-expert size C. Tokens beyond capacity are dropped: their MoE output is zero and only the residual connection carries them forward.
  • CF = 1.0 wastes no compute but drops under any imbalance; CF = 1.25–2.0 is common in training. Dropless implementations (MegaBlocks-style block-sparse grouped GEMMs) avoid dropping at the cost of variable shapes.
  • At inference, dropping makes outputs depend on what else is in the batch. Most serving stacks run dropless.

  • Without the auxiliary loss the router collapses: two experts receive no tokens and one receives 2%, four experts are overloaded at ~22% against a capacity of 15.6% (1.25 × 1/8), and 24.5% of token-slots are dropped. MSE is 6× worse because dead experts are wasted parameters and dropped tokens get no FFN.
  • With \alpha = 0.01 load is near uniform, the aux term sits at its minimum of 1.0, nothing is dropped and MSE is best.
  • With \alpha = 0.1 balance is tighter but MSE is slightly worse: the balance objective starts to fight the task. This is the tuning tension that motivated DeepSeek-V3's loss-free bias approach.
  • The collapse needed two realistic triggers: a small initial skew and non-zero-mean inputs (residual-stream activations are not centred). With zero-mean inputs and no skew, the same toy stayed roughly balanced; collapse is a dynamics problem, not a certainty.
Implementation Note
  • The Python loop over experts is for clarity. Production code sorts token-slots by expert and runs one grouped GEMM (or a block-sparse kernel) over all experts.
  • Compute the router in float32. Switch Transformer's "selective precision" found bf16 routers unstable Documented (Fedus et al., 2021).
  • Log per-expert load, dropped fraction and router entropy every step. They are the earliest signal of an unhealthy MoE run.

Expert Parallelism and the All-to-All

  • Attention and dense layers run data-parallel (or TP); experts are sharded across the expert-parallel group. GShard (Lepikhin et al., 2020) introduced this pattern at 600B parameters.
  • Communication per MoE layer per GPU is about 2 \cdot N_{\text{local}} \cdot k \cdot d \cdot b bytes (dispatch plus combine). With k=8 and d=7168 (DeepSeek-V3 shapes) that is ~230 KB per token per layer in bf16, which is why V3 dispatches in FP8 and limits each token to at most 4 nodes Documented (V3 report).
  • All-to-all over InfiniBand is much slower than NVLink. Topology-aware routing (node-limited), overlapping communication with computation (DualPipe in V3) and larger micro-batches are the standard mitigations.
  • Load imbalance becomes a latency problem: the all-to-all waits for the slowest GPU. Balance matters for throughput even when nothing is dropped.

Fine-Grained and Shared Experts

  • Fine-grained segmentation: split each expert into m smaller ones and route to mk of them. Same FLOPs and parameters, far more possible expert combinations, so experts can specialise more narrowly (Dai et al., 2024).
  • Shared experts: one or more experts that every token always uses. They absorb common knowledge (syntax, frequent patterns) so routed experts do not all relearn it.
  • Configurations Documented: Mixtral 8x7B uses 8 experts, top-2, no shared experts, 47B total / 13B active (Jiang et al., 2024). DeepSeek-V2 uses 2 shared + 160 routed, 6 active, 236B / 21B. DeepSeek-V3 uses 1 shared + 256 routed, 8 active, 671B / 37B.
  • Mixtral's authors found no obvious topic-level specialisation of experts; routing correlated more with syntax and token identity Documented. Do not assume "the maths expert" exists.

Simple version

  • Top-2 over 8 experts, Switch aux loss, CF 1.25, all experts on one GPU. Works up to a few billion parameters.

Production version

  • Fine-grained plus shared experts, dropless grouped GEMM, float32 router with z-loss or bias balancing, expert parallelism across nodes with node-limited routing, FP8 dispatch, communication overlapped with compute, per-expert telemetry.

Why it is complicated

  • Routing is discrete, so balance and quality are coupled through a non-differentiable choice.
  • Serving needs all experts resident: a 671B MoE needs a multi-GPU deployment even though each token touches only 37B parameters. MoE lowers FLOPs per token, not the memory floor.
  • At small batch, each expert sees few tokens, so decode reads many expert weights for little work; MoE's advantage appears at high batch.
  • Router collapse: a few experts take most tokens; others die. Detect via load entropy; fix with aux loss, z-loss, bias balancing, lower LR on the router.
  • Loss spikes from exploding router logits in bf16. Use float32 routing and z-loss.
  • Silent token dropping in evaluation or serving, making outputs batch-dependent. Run dropless at inference.
  • Straggler experts in expert parallelism: throughput set by the hottest GPU.
  • Fine-tuning instability: small SFT datasets can unbalance routers trained on trillions of tokens. Freeze the router or keep the aux loss on during fine-tuning.

Evaluation

  • Compare against a dense model at equal active FLOPs and, separately, equal total parameters; both comparisons are needed to make an honest claim.
  • Track expert load histograms per layer, dropped-token rate, all-to-all time share and tokens per second per GPU.

Sparse and Local Attention

Most attention mass in a trained model is local. Restricting each query to a window of recent keys bounds the KV cache and makes attention linear in sequence length. The catch is that models also depend on a few distant tokens in ways that are not obvious, and removing them can destroy the model.

The Engineering Problem

Full causal attention costs O(T^2) in prefill and an unbounded KV cache in decode. For streaming applications (long chats, agents that run for hours) the cache must stop growing. The obvious fix, evicting old tokens, turns out to break models badly.

Possible solutions and what each does not solve

  • Sliding window (local) attention: each token sees the last W keys. Bounded cache; information beyond W travels only indirectly through layers (receptive field \approx L \cdot W).
  • Dilated and strided patterns (Child et al., 2019; Beltagy et al., 2020): widen the receptive field at the same cost; irregular memory access, poor kernel support.
  • Block-sparse with global tokens (Longformer, BigBird): a few tokens attend everywhere; good for encoders and documents, awkward for causal decode.
  • Interleaved local and global layers (Gemma 2 alternates 1:1; Gemma 3 uses 5 local : 1 global) Documented (Gemma Team, 2024; 2025): most layers get a small cache; the global layers keep long-range retrieval.
  • Attention sinks (Xiao et al., 2023): keep the first few tokens in the cache forever. Cheap fix for window eviction; does not restore access to evicted content.

Attention Sinks

  • Observation (Xiao et al., 2023): trained LLMs put a large share of attention on the first token(s), regardless of their content. Softmax must sum to 1; when a head has nothing useful to attend to, it parks its mass on a token that every query can see, and the first token is the only such token in causal training.
  • Consequence: evict the first tokens (plain sliding window over a cache) and the softmax redistributes that mass onto real tokens, corrupting every layer. Perplexity explodes.
  • StreamingLLM fix: keep 4 initial tokens plus a rolling window. They report stable language modelling up to 4 million tokens and up to 22.2× speed-up over sliding window with recomputation Documented.

  • A 64-key window without sinks multiplies perplexity by 11×. Adding back four tokens recovers most of it (54.6 vs 41.2). The remaining gap is genuine long-range information lost to the window.

Designing Sinks In
  • Rather than relying on an emergent sink, models can be given one: a learnable sink token prepended in pretraining (Xiao et al., 2023), or a per-head learnable logit added to the softmax denominator ("off-by-one" softmax, or sink logits as used in some recent open-weight models).
  • Sinks also explain massive activations and outlier features that complicate quantisation (Volume 12): the sink token's hidden state has a few huge dimensions.

  • Evicting the first tokens of a cache (e.g. naive truncation of a long chat): perplexity collapse, as measured above.
  • Window smaller than the task's dependency length: fluent output that ignores the instruction given 10K tokens ago. Needle tests (Chapter 5) catch this; perplexity does not.
  • Mismatched windows between training and serving (a serving engine ignoring the model's window config) change outputs silently.

Long Context

Pretraining at 128K tokens from the start is prohibitively expensive, so models are pretrained short (4K–8K) and extended late. Extension is mostly a question of what RoPE does beyond the trained length, followed by a short continued-pretraining phase on long data. Whether the model then uses the context is a separate question, answered only by evaluation.

The Engineering Problem

A model trained at 4K positions and run at 16K sees rotation angles in its slow RoPE dimensions that it never saw in training. Attention scores for those dimensions become out-of-distribution, and quality collapses within a few hundred tokens past the trained length.

What RoPE Does Beyond the Trained Length

RoPE rotates each pair i of query/key dimensions by angle m\theta_i at position m:

\theta_i = b^{-2i/d}, \quad i = 0,\dots,\tfrac{d}{2}-1, \qquad \lambda_i = \frac{2\pi}{\theta_i} \ \ (\text{wavelength in tokens})
  • Fast pairs (small i) complete hundreds of rotations within the training length: every angle has been seen, so they extrapolate fine.
  • Slow pairs (large i) have wavelengths longer than the training context: they never complete a rotation, and positions beyond L produce angles the model has never seen.

Scaling methods (extension factor s = L'/L)

  • Position interpolation (PI) (Chen et al., 2023): \theta_i' = \theta_i / s for all pairs. Every angle is in range, but fast pairs lose resolution: neighbouring tokens become 4× closer in angle. Needs fine-tuning (they used about 1000 steps to reach 32K on LLaMA).
  • NTK-aware scaling (community proposal, 2023): change the base, b' = b \cdot s^{d/(d-2)}. Fast pairs are nearly untouched; the slowest pair is interpolated by exactly s; middle pairs partially. Works reasonably without fine-tuning; "dynamic NTK" recomputes s from the current length.
  • YaRN (Peng et al., 2023): interpolate per pair depending on how many rotations it completes in L, plus an attention temperature.
r_i = \frac{L}{\lambda_i}, \qquad \gamma(r) = \begin{cases} 0 & r < \alpha \\ 1 & r > \beta \\ \frac{r-\alpha}{\beta-\alpha} & \text{otherwise} \end{cases}, \qquad \theta_i' = \big(1-\gamma(r_i)\big)\frac{\theta_i}{s} + \gamma(r_i)\,\theta_i
\text{softmax}\!\left(\frac{q^\top k}{t\sqrt{d}}\right), \qquad \sqrt{1/t} = 0.1 \ln s + 1
  • Pairs with many rotations (r > \beta = 32) are left alone; pairs with less than one rotation (r < \alpha = 1) are fully interpolated; a linear ramp in between. \alpha, \beta are the values recommended for LLaMA Documented.
  • The temperature compensates for attention entropy increasing as more keys compete. YaRN reports extension of LLaMA 2 to 128K with roughly 0.1% of the original pretraining data Documented.
  • Other production variants: raising the RoPE base before long-context training ("ABF", Xiong et al., 2023; Code Llama uses b = 10^6; Llama 3 uses 5\times10^5), and Llama 3.1's piecewise frequency scaling, which is YaRN-like in spirit.

Long-Context Training Data

  • Position scaling makes long inputs possible; continued pretraining on long documents makes them useful. Typical recipes use a few billion tokens at the target length.
  • Upsample naturally long documents (books, code repositories concatenated in dependency order, long papers) without distorting the domain mix; Fu et al. 2024 found per-source upsampling of long documents better than upsampling long-heavy domains Documented.
  • Keep a share of short data to avoid short-context regressions; evaluate both.
  • Use document masking in packed sequences so attention does not cross document boundaries (Volume 4); otherwise "long context" training is mostly unrelated snippets.
  • Systems: long sequences need sequence or context parallelism (ring attention) and activation checkpointing (Volume 6).

Evaluating Long Context

A needle-in-a-haystack harness

  • Insert a unique fact (the needle) at a controlled depth in filler text of controlled length; ask for it; grade exactly. Sweep depth × length.
  • Add distractors (similar-looking facts) so that "return the only number" does not pass the test.
  • The model is behind an interface, so the same harness runs against a real endpoint. Here a mock with deliberately U-shaped recall and a cliff beyond its trained length stands in, to test the harness itself.

  • Seeding the mock by a hash of the prompt makes results reproducible and cacheable; do the same with real endpoints by caching responses keyed on prompt hash and sampling parameters.

Lost in the middle

  • Liu et al. 2023 placed the answer-bearing document at different positions among 20 retrieved documents. Accuracy was highest when it was first or last and lowest in the middle, a U-shaped curve, for every model tested, including ones marketed for long context Documented.
  • In some settings, middle-position accuracy fell below the closed-book (no documents) baseline Documented.
  • Engineering consequence for RAG (Volume 9): put the most relevant chunks at the start and end of the context, retrieve fewer and better chunks, and never assume a longer context window reduces the need for ranking.

Beyond needles: RULER

  • Single-needle retrieval is nearly solved and over-flatters models. RULER (Hsieh et al., 2024) adds multi-key and multi-value needles, variable tracking (multi-hop), aggregation (common and frequent words) and QA, with configurable length.
  • RULER found that most models claiming 32K+ contexts fell well below their short-context performance before reaching the claimed length; its "effective length" is often a fraction of the advertised one Documented.
Warning
  • Perplexity on long documents is a weak long-context metric: most tokens are predictable from local context, so a model that ignores everything beyond 4K can show good long-document perplexity.
  • Needle tests with filler that is semantically unrelated to the needle are easy. Use realistic haystacks and distractors from the same distribution as the needle.
  • Scaling config lost in deployment: the serving engine loads the model without its rope_scaling block, so long prompts silently degrade.
  • Static scaling hurting short prompts: PI-style scaling applied to all lengths slightly worsens short-context quality; dynamic scaling or YaRN avoids most of this.
  • Claimed context ≠ usable context: accept a context length only after a RULER-style curve at your task's lengths.
  • KV memory: a model that can read 128K tokens may not be servable at 128K at your batch size (Chapter 2).

Linear Attention and State Space Models

Softmax attention keeps every past token. Recurrent models keep a fixed-size state. Linear attention and state space models (SSMs) are attempts to get a Transformer's parallel training with an RNN's constant-memory inference. The best current answer is not a replacement but a hybrid.

The Engineering Problem

Decode memory and time per token for softmax attention grow linearly with context, and prefill grows quadratically. A model with a constant-size state would have flat decode cost at any length. RNNs had that, but trained sequentially and forgot. Can we train in parallel and infer recurrently without forgetting what matters?

Linear Attention as an RNN

Replace \exp(q^\top k) with a kernel \phi(q)^\top\phi(k) (Katharopoulos et al., 2020). Associativity then lets the sum over past keys be accumulated once:

y_t = \frac{\sum_{s \le t} \phi(q_t)^\top \phi(k_s)\, v_s}{\sum_{s \le t} \phi(q_t)^\top \phi(k_s)} = \frac{\phi(q_t)^\top S_t}{\phi(q_t)^\top z_t}, \qquad S_t = S_{t-1} + \phi(k_t) v_t^\top, \quad z_t = z_{t-1} + \phi(k_t)
  • Training uses the parallel (masked matrix) form, or chunked forms that mix both; inference uses the recurrence with an O(d \cdot d_v) state.
  • \phi(x) = \mathrm{elu}(x) + 1 keeps scores positive.
parallel vs recurrent max|diff| = 5.96e-07
recurrent state: 4160 floats, independent of T
softmax KV cache at T=256: 32768 floats, grows with T
  • The two forms agree to float precision: linear attention is an RNN.
  • Why it underperforms softmax: the state only ever adds; nothing is forgotten, and a d \times d_v matrix has limited capacity, so retrieval of specific past tokens degrades as the sequence grows. Softmax sharpness is also lost.
  • Later designs add decay or gating: RetNet (fixed decay), GLA (data-dependent gates), DeltaNet (delta-rule updates that overwrite rather than add), RWKV. These are all variations of "what should the state forget and when".

State Space Models: S4 to Mamba

A continuous linear SSM maps input x(t) to output y(t) through hidden state h(t); discretised with step \Delta:

h_t = \bar{A} h_{t-1} + \bar{B} x_t, \qquad y_t = C h_t + D x_t, \qquad \bar{A} = \exp(\Delta A), \quad \bar{B} \approx \Delta B
  • S4 (Gu et al., 2021): A, B, C, \Delta are fixed per channel (linear time-invariant). The recurrence unrolls into a convolution with kernel K_j = C\bar{A}^j\bar{B}, so training is a long FFT convolution and inference is a recurrence. Structured (HiPPO-initialised) A gives long memory.
  • The LTI limitation: the same dynamics apply to every token. The model cannot decide to ignore filler or to store one important token, so it is weak at content-based selection (copying, associative recall).
  • Mamba (Gu & Dao, 2023): make \Delta_t, B_t, C_t functions of the input (\Delta_t = \mathrm{softplus}(W_\Delta x_t + b)). Large \Delta_t means "reset and write this token"; small means "ignore it and keep the state". The convolution form is lost, so Mamba uses a hardware-aware parallel scan kept in SRAM.
LTI scan vs convolution max|diff| = 6.66e-16
trace of token 5 at t=63: fixed delta 1.27e-13, selective delta 0.472
  • With constant parameters the scan equals a convolution: that is S4's training trick.
  • With a fixed step, a single fact decays to 10^{-13} over 58 tokens. With a token-dependent step (write at token 5, tiny steps afterwards) the same state keeps 47% of it. Selectivity is what lets a fixed-size state hold on to specific information.
  • The state is still finite. Mamba-class models lag attention on tasks that need exact recall of arbitrary earlier content (copying long strings, multi-key retrieval), which motivates hybrids.
Mamba-2 and the Duality
  • Mamba-2 (Dao & Gu, 2024) restricts \bar{A} to a scalar per head and shows the resulting SSM equals a form of masked linear attention with a decay mask ("structured state space duality"). Training can then use matrix multiplications (tensor cores) in chunks, which is much faster than a scan.
  • The families have converged: gated linear attention, RetNet, Mamba-2 and DeltaNet are all linear recurrences with different state-update rules.

Hybrids

  • Jamba (Lieber et al., 2024): one attention layer per eight (1:7 attention to Mamba), MoE in every other layer, 52B total / 12B active, 256K context. They report fitting 140K tokens of context on a single 80 GB GPU Documented.
  • Several later open models (e.g. Zamba, Samba, NVIDIA's Nemotron-H, MiniMax-01 with lightning attention) combine a minority of softmax attention layers with a majority of linear-recurrent or local layers Documented in their respective reports.
  • Why hybrids work Inferred: a few global attention layers provide exact retrieval; recurrent layers provide cheap local and summarised context. The KV cache is only paid for the attention layers, so a 1:7 ratio cuts cache by about 8×.

Multi-Token Prediction and Other Objectives

Next-token prediction is not the only way to train a decoder. Small changes to the objective or the input format give models new abilities (filling in code between a prefix and a suffix), denser training signal, or a built-in draft model for faster decoding.

The Engineering Problem

Next-token loss gives one supervised signal per position and rewards short-horizon prediction. Code editors need insertion, not continuation. Decoding produces one token per forward pass, leaving compute idle. Each of these can be addressed by the objective rather than by a new architecture.

Multi-Token Prediction

  • Gloeckle et al. 2024: a shared trunk feeds n independent output heads; head i predicts token t+i. The loss is the sum of the n cross-entropies.
  • Reported effects Documented: gains grow with model size; a 13B model solved 12% more HumanEval and 17% more MBPP problems than a next-token baseline; with self-speculative decoding, 4-token models ran up to 3× faster at inference.
  • DeepSeek-V3 uses sequential MTP modules (each extra prediction conditions on the previous one's representation, keeping a causal chain), depth 1. They report 85–90% acceptance for the second token and about 1.8× tokens per second when used for speculative decoding Documented (V3 report).
\mathcal{L}_{\text{MTP}} = -\sum_{t} \sum_{i=1}^{n} \log p_{\theta_i}\!\left(x_{t+i} \mid h_t\right), \qquad h_t = f_{\text{trunk}}(x_{\le t})
per-head loss: t+1=0.83 t+2=1.41 t+3=1.89 t+4=2.29
mean tokens accepted per forward pass: 4.00 (max 4)
  • Loss rises with horizon, as it must: with 10% noise per step, predicting 4 ahead compounds uncertainty. The entropy floor for t+1 here is about 0.73 nats, so head 1 is near optimal after 200 steps.
  • Acceptance is perfect only because greedy decoding on this toy follows the successor table deterministically. Real text gives lower acceptance; Gloeckle et al. report ~3× on code at best.
  • Verification uses the same model's head 1, so outputs are identical to plain greedy decoding: speculation changes speed, never content.
Implementation Note
  • With a 128K–256K vocabulary, n heads' logits dominate activation memory. Gloeckle et al. compute each head's forward and backward sequentially, accumulating gradient at the trunk output, so only one head's logits are alive at a time.
  • At inference, the extra heads can be dropped entirely; the trunk is a normal next-token model.

Fill-in-the-Middle

  • Problem: a code editor's cursor sits between a prefix and a suffix. A left-to-right model cannot condition on the suffix.
  • Bavarian et al. 2022: cut a document at two random points into prefix, middle and suffix; move the middle to the end with sentinel tokens; train normally. The model learns infilling with ordinary next-token loss.
  • Reported Documented: at a FIM rate of 50%, left-to-right performance is essentially unchanged ("FIM for free"); character-level span selection works better than line- or token-level; applying FIM in pretraining is more effective than fine-tuning it in later.

  • Split at the character level during training, but at inference the cursor may sit mid-token: tokenisation of the prefix boundary (Volume 3) is a real source of FIM quality bugs.

Prefix LM

  • Tokens in the prefix (instruction, image patches, input document) attend bidirectionally; the rest is causal. Loss is computed only on the causal part. The mask printed above shows a 3-token bidirectional prefix.
  • Used by T5-style models, UniLM and several vision-language models for their image tokens. Wang et al. 2022 found non-causal decoders with an MLM-style objective strong for zero-shot after multitask fine-tuning, but causal decoders best for pure zero-shot generation Documented.
  • Why decoders stayed causal Inferred: causal training gives a loss on every token, one mask for all data, and trivially reusable KV caches in multi-turn chat. A bidirectional prefix invalidates the cache whenever the prefix changes.
  • FIM sentinel mismatch between training and the IDE plugin: model continues instead of infilling.
  • FIM rate too high in non-code data: small left-to-right regressions; ablate per domain.
  • MTP at small scale: Gloeckle et al. found MTP can hurt small models; gains appear at billions of parameters.

Reading Modern Model Reports

Much of what the field knows about frontier architectures comes from technical reports written partly for engineers and partly for marketing. A senior engineer reads them like an incident report: extract the facts, record where each came from, mark what is inferred, and discard claims that cannot be checked.

The Engineering Problem

Reports mix exact configuration tables, ablations at one scale, benchmark tables with unspecified prompting, and adjectives. Decisions made from them (which architecture to adopt, which model to serve) inherit whatever was not verified.

A Structured Reading Method

  1. Configuration first. Find the architecture table: layers, d_{\text{model}}, heads, KV heads, head dim, FFN size, vocabulary, experts (total, active, shared), context length, RoPE base and scaling. Compute parameters and KV bytes per token yourself and check they match the headline numbers.
  2. Training budget. Tokens, data mixture description, sequence-length schedule, compute (GPU-hours), precision (FP8?), parallelism. Compute 6ND and compare with the stated GPU-hours for plausibility.
  3. What changed versus the previous version? List each change and whether an ablation supports it, at what scale.
  4. Evaluation hygiene. For every benchmark: shots, prompt format, chain-of-thought or not, sampling, pass@k, whether baselines were run by the authors or copied. Look for contamination analysis.
  5. Long-context claims. Is there a RULER-style curve or just a single-needle heatmap?
  6. Systems claims. Throughput numbers: which hardware, batch size, context, engine, precision, versus which baseline?
  7. What is missing. Data sources, failed runs, instabilities, safety evaluation details. Absence is information.
  8. Ledger. Record every claim as Documented (with section/table), Inferred (with your reasoning) or Marketing (no checkable evidence).

Volume Review

What You Learned

  • Decode is memory-bound; at serving batch sizes the KV cache, not the weights, dominates bytes per step. \text{KV} = 2 L n_{kv} d_h T b.
  • MQA, GQA and MLA reduce KV bytes per token by sharing or compressing heads; MLA's absorption trick attends directly over latents; decoupled RoPE keeps absorption valid.
  • MoE separates parameters from FLOPs; routers collapse without balancing; capacity factors trade compute for dropped tokens; expert parallelism turns balance into a latency problem.
  • Sliding windows bound the cache; attention sinks explain why naive eviction destroys models.
  • RoPE extrapolation fails in slow dimensions; PI, NTK and YaRN differ in which dimensions they interpolate.
  • Needle tests, RULER and "lost in the middle" measure whether context is used, not just accepted.
  • Linear attention is an RNN; selective SSMs add input-dependent forgetting; hybrids keep a few attention layers for exact recall.
  • MTP, FIM and prefix LM change the objective or format, not the architecture.
  • Reports are read with a ledger: Documented, Inferred, Marketing.

Failure Modes

  • KV heads mis-grouped on checkpoint load: plausible but degraded outputs.
  • Router collapse and token dropping in MoE: dead experts, batch-dependent outputs.
  • Cache eviction without sinks: perplexity collapse in streaming.
  • Missing RoPE scaling config at serving: long-prompt degradation with no error.
  • Long-context claims from single needles: effective length far below advertised.
  • Recurrent-state precision loss in SSMs; train/infer kernel mismatch.
  • FIM sentinel mismatch between model and editor.
  • Unsourced report claims driving architecture decisions.

Evaluation

  • Parity tests for every efficient path: cached vs full, absorbed vs naive, recurrent vs parallel, scan vs convolution.
  • Analytic and measured KV bytes per token, maximum batch at target context, tokens per second.
  • MoE health: per-expert load, dropped fraction, router entropy, all-to-all time share.
  • Long context: RULER-style tasks by length and depth, with distractors and at least 50 trials per cell; short-context regression suite.
  • Quality comparisons at equal active FLOPs and at equal total parameters.

  4. Measure dropped tokens as a function of capacity factor (1.0, 1.25, 2.0) for the collapsed and balanced routers.
  5. Implement a rolling-buffer KV cache with sinks and positions re-indexed within the cache; verify it matches the masked version for the first W tokens.
  6. Add dynamic NTK scaling (s = \max(1, T/L) recomputed per call) and compare its unseen-angle count with static NTK across lengths.
  7. Add multi-key and variable-tracking tasks to the needle harness.
  8. Add a scalar decay \gamma to linear attention (RetNet-style) in both forms and keep the parity test passing.
  9. Make \Delta_t in the selective scan a learned function of x_t and train it to copy a marked token across a gap.
  10. Train the MTP toy with n = 1 and n = 4 and compare the next-token loss of head 1.

Research Papers

RESEARCH PAPER Fast Transformer Decoding: One Write-Head is All You Need Shazeer, 2019 · arXiv
Problem
Incremental decoding is bottlenecked by loading keys and values.
Previous limitation
MHA caches K/V for every head.
Approach
Multi-query attention: all heads share one K and V.
Contribution
Large decoding speed-ups with minor quality loss.
Practical impact
Adopted by PaLM and Falcon; precursor to GQA.
Limitations
Quality loss and instability at scale.
RESEARCH PAPER GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints Ainslie et al., 2023 · EMNLP
Problem
MQA is fast but loses quality; retraining is expensive.
Previous limitation
Binary choice between MHA and MQA.
Approach
Grouped K/V heads; uptrain MHA checkpoints by mean-pooling with ~5% extra compute.
Contribution
Near-MHA quality at near-MQA speed.
Practical impact
Default attention in most open LLMs since 2023.
Limitations
Evaluated on T5 encoder-decoder tasks.
RESEARCH PAPER DeepSeek-V2: A Strong, Economical, and Efficient Mixture-of-Experts Language Model DeepSeek-AI, 2024 · arXiv
Problem
KV cache and training cost at frontier scale.
Previous limitation
GQA trades quality for cache; MoE balance costs quality.
Approach
Multi-head latent attention with decoupled RoPE; DeepSeekMoE.
Contribution
93.3% smaller KV cache and 5.76× generation throughput vs DeepSeek 67B.
Practical impact
MLA reused in V3 and R1; spawned MLA kernels.
Limitations
Complex; hard to retrofit into existing models.
RESEARCH PAPER Outrageously Large Neural Networks: The Sparsely-Gated Mixture-of-Experts Layer Shazeer et al., 2017 · ICLR
Problem
Capacity limited by compute per example.
Previous limitation
Conditional computation was impractical on GPUs.
Approach
Noisy top-k gating between LSTM layers; importance and load losses.
Contribution
Models up to 137B parameters with modest compute.
Practical impact
Foundation of all modern MoE.
Limitations
Instability and communication cost left to later work.
RESEARCH PAPER Switch Transformers: Scaling to Trillion Parameter Models with Simple and Efficient Sparsity Fedus, Zoph and Shazeer, 2021 · JMLR 2022
Problem
MoE complexity, instability and communication.
Previous limitation
Top-2 or more routing assumed necessary.
Approach
Top-1 routing, simplified aux loss, capacity factor, float32 router, smaller init.
Contribution
Up to 7× pretraining speed-up over T5 at equal FLOPs; 1.6T parameters.
Practical impact
The aux loss used in most later MoEs.
Limitations
Fine-tuning instability; token dropping.
RESEARCH PAPER Mixtral of Experts Jiang et al., 2024 · arXiv
Problem
Open models with strong quality per active parameter.
Previous limitation
Few open, competitive MoE LLMs.
Approach
Mistral 7B architecture with 8 experts per layer, top-2.
Contribution
47B total / 13B active, matching or beating Llama 2 70B on many benchmarks.
Practical impact
Made MoE mainstream in open-weight serving.
Limitations
Little training data disclosure.
RESEARCH PAPER Efficient Streaming Language Models with Attention Sinks Xiao et al., 2023 · ICLR 2024
Problem
Infinite-length streaming with bounded memory.
Previous limitation
Window attention collapses once initial tokens are evicted.
Approach
Keep ~4 initial "sink" tokens plus a rolling window.
Contribution
Explained sinks; stable modelling to 4M tokens.
Practical impact
Supported in serving engines; influenced sink designs.
Limitations
Does not extend what the model can recall.
RESEARCH PAPER Extending Context Window of Large Language Models via Positional Interpolation Chen et al., 2023 · arXiv
Problem
RoPE models fail beyond trained length.
Previous limitation
Extrapolation is unstable.
Approach
Linearly downscale positions; brief fine-tuning.
Contribution
LLaMA extended to 32K with ~1000 steps.
Practical impact
First widely used extension method.
Limitations
Loses local positional resolution.
RESEARCH PAPER YaRN: Efficient Context Window Extension of Large Language Models Peng et al., 2023 · ICLR 2024
Problem
PI blurs local positions; NTK partially extrapolates.
Previous limitation
Uniform treatment of RoPE dimensions.
Approach
Per-dimension ramp by wavelength plus attention temperature.
Contribution
128K LLaMA 2 with far less fine-tuning data.
Practical impact
Used by DeepSeek and Qwen long-context models.
Limitations
Hyperparameters tuned for LLaMA; usable length still needs evaluation.
RESEARCH PAPER Lost in the Middle: How Language Models Use Long Contexts Liu et al., 2023 · TACL 2024
Problem
Do models use all of their context?
Previous limitation
Context length reported as a capability without position analysis.
Approach
Vary answer position in multi-document QA and key-value retrieval.
Contribution
U-shaped accuracy by position across models.
Practical impact
Changed RAG context ordering and evaluation practice.
Limitations
Models of 2023; newer models reduce but do not eliminate the effect.
RESEARCH PAPER Transformers are RNNs: Fast Autoregressive Transformers with Linear Attention Katharopoulos et al., 2020 · ICML
Problem
Quadratic attention cost.
Previous limitation
Efficient attention variants lacked constant-memory decoding.
Approach
Kernel feature maps; associativity gives a recurrent form.
Contribution
Linear-time training and constant-memory decode.
Practical impact
Basis of RetNet, GLA, DeltaNet and hybrid layers.
Limitations
Weaker recall than softmax attention.
RESEARCH PAPER Mamba: Linear-Time Sequence Modeling with Selective State Spaces Gu and Dao, 2023 · COLM 2024
Problem
LTI SSMs cannot select content.
Previous limitation
S4-style models lagged Transformers on language.
Approach
Input-dependent \Delta, B, C; hardware-aware parallel scan.
Contribution
Transformer-competitive language modelling with linear scaling and ~5× inference throughput.
Practical impact
Used in hybrids such as Jamba.
Limitations
Finite state limits exact recall.
RESEARCH PAPER Better & Faster Large Language Models via Multi-token Prediction Gloeckle et al., 2024 · ICML
Problem
Next-token loss is a local, sample-inefficient signal.
Previous limitation
Earlier multi-token work at small scale.
Approach
Shared trunk with n independent heads; memory-efficient sequential backward.
Contribution
Better code benchmarks at scale; up to 3× faster self-speculative decoding.
Practical impact
MTP adopted (sequentially) in DeepSeek-V3.
Limitations
Can hurt small models; gains mostly on code.
