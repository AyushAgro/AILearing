Enterprise Constraints as Requirements

Latency SLOs, residency pins, identity providers, audit retention and change control are not "phase two". In enterprise deals they are acceptance criteria. ADRs that survive security review treat them as requirements with owners and evidence.

The Engineering Problem

A platform ships a brilliant RAG agent. Security review asks: which IdP? which region pin? where do prompts land? who can change the system prompt? The team answers "we can configure that later". Procurement stalls. The architecture was never wrong on accuracy — it was incomplete on enterprise constraints.

Possible approaches

  • Checklist theatre. Tick SOC 2 boxes in a slide. No delete path, no tenant filter proof, no claim map. Fails the first technical questionnaire.
  • Defer identity and residency. Demo on a shared SaaS key. Rework cost appears at pilot — Volume 27 already warned about this.
  • Constraints as ADRs. Each constraint becomes a decision record with owner, evidence artefact and residual risk. This volume's default.
Key Idea
  • Enterprise constraints are product requirements with testable artefacts, not legal poetry pasted into a README.
  • If a control cannot produce evidence (log row, deny test, delete receipt), it will not survive review.

Identity and Access

OIDC/SAML SSO, SCIM provisioning, service accounts and least privilege for tools and agents are the identity fabric. Agents inherit the caller's permissions — or they become confused deputies (Volume 17).

The Engineering Problem

The agent runs as a superuser service account "because tools need access". A low-privilege user asks for a refund; the tool succeeds against every tenant. SSO was "done" because humans can log in. Machine identity and claim propagation were never designed.

Possible approaches

  • App-local users. Fast for demos; fails every enterprise questionnaire.
  • SSO for humans, god-mode for agents. Common failure mode.
  • SSO + claim map + scoped service accounts. Humans via OIDC; connectors via short-lived, tenant-scoped credentials; tools check claims before side effects.

SCIM and leavers
  • Documented SCIM 2.0 (RFC 7644) is the common provisioning protocol IdPs use to create/update/deactivate users.
  • Deprovision SLA belongs in the engagement brief: leaver loses tool rights within N hours, verified by a periodic orphan-account job.
  • Service accounts are not humans: no interactive SSO; rotate and scope separately.
SAML versus OIDC
  • Documented Many enterprises still present SAML 2.0 for workforce SSO. Prefer OIDC when available for API-friendly tokens; if SAML is mandatory, bridge to internal JWTs at the edge and keep the same claim map.
  • Do not maintain two authorization logics — normalise to one internal principal object before tenancy middleware runs.

Tenancy Models

Shared versus siloed tenancy, row-level versus project-level isolation and cross-tenant leakage tests decide whether one bug becomes one breach or every customer's breach.

The Engineering Problem

Vectors live in one index "for cost". Tenant id is a metadata field the retriever should filter. A missing filter ships. Customer B sees Customer A's contracts in a citation. The model was fine; the tenancy contract was ambient.

  • Tenant context is request-scoped and fail-closed. No ambient "default tenant".

Cross-tenant leakage tests (preview)

  • Same object id across tenants must not collide in authorization — include tid in the authorization key, not only in presentation.
  • Caches (KV, HTTP, embedding) must be tenant-keyed or disabled for sensitive paths.
  • Background jobs inherit tenant context explicitly; cron without tid is a classic leak class.

Data Residency and Retention

Region pinning, deletion and export paths, training-data policies and BYOK/CMEK patterns are how residency promises become code — and how "we delete it" becomes a receipt.

The Engineering Problem

Marketing says "EU data stays in the EU". Inference calls a global API. Embeddings land in a US vector host. Prompt logs ship to a US observability vendor. No single component lied; the composition violated the promise.

Possible approaches

  • Trust the vendor region dropdown. Necessary but not sufficient — check subprocessors and log exporters.
  • Pin every store and deny cross-region writes. Policy engine + tests.
  • BYOK/CMEK. Customer-managed keys so destruction of key material is a hard stop on ciphertext — still needs region pin for plaintext paths.

Documented Cloud providers publish region catalogues and CMEK/BYOK features for storage and some AI services. Inferred An AI stack's true residency surface includes prompt logs, eval sets, fine-tune corpora, support exports and laptop caches — map them explicitly.

deny prompts region us-east-1 not in ['eu-central-1', 'eu-west-1'] for acme
prompt_expiry 2026-01-31
due True
Training-data policy
  • Default for enterprise: customer prompts are not training data unless a signed opt-in says otherwise — encode as a boolean on the tenant record and refuse fine-tune export jobs when false.
  • Delete/export must cover vectors, chat history, tool traces and eval clones of customer text.
  • BYOK/CMEK: document key custody, rotation and what happens when the customer revokes the key mid-flight (fail requests; do not silently fall back to provider keys).

Private Networking

VPC peering and Private Link–style patterns, egress allow-lists and "no public model endpoints" are how residency and confidentiality survive the network path — not just the database row.

The Engineering Problem

The app runs in a private subnet. The model call goes to a public HTTPS API because "TLS is enough". A data-loss questionnaire asks for private connectivity. The architecture diagram never showed the public hop. Procurement adds six weeks.

Trade-off
  • Private endpoints do not replace authn/authz or tenancy filters.
  • Allow-lists that block security patches (CVE package mirrors) get "temporarily" disabled — prefer a documented emergency mirror inside the allow-list.

DNS and certificates

  • Private endpoints fail silently when DNS still resolves to the public hostname. Prove with a health check that captures the resolved address family and that TLS verifies against the expected SAN.
  • Do not disable TLS "for the PoC". Volume 27 already lists this as a kill criterion cousin; this volume treats it as a hard deny in the deploy pack.
  • Documented Cloud private-connectivity guides emphasise zonal redundancy for interface endpoints — plan multi-AZ before a single-AZ outage becomes an availability incident blamed on "the model".

Secrets, Keys and Audit Trails

Vault integration, short-lived credentials and immutable audit logs for prompts and tools are the difference between "we take security seriously" and evidence an auditor or incident commander can use.

The Engineering Problem

API keys live in a .env on a laptop and in a Slack thread. Prompt logs capture full customer text in a mutable database someone can UPDATE. After an incident, nobody can prove which tool ran under which subject. The post-mortem is archaeology.

Key Idea
  • Secrets are fetched at runtime with short TTL; never baked into images or prompts.
  • Audit rows are append-only, hashed or externally copied, and redacted for PII according to policy — completeness and confidentiality both matter.
chain_ok True
n_events 2
Vault and short-lived creds
  • Prefer workload identity → vault/KMS → ephemeral DB/API tokens over long-lived static keys.
  • Rotate connector secrets on a schedule and on leaver events for human-tied tokens.
  • Prompt bodies in audit: store hashes or redacted excerpts by default; full text only under a separate retention and access policy.

Procurement and Vendor Risk

DPAs, subprocessors, model-provider terms and open-weight versus hosted trade-offs decide whether your elegant architecture is buyable. Engineers who ignore procurement write systems that cannot be signed.

The Engineering Problem

Legal asks for a subprocessor list, training-use clause and data-return timeline. The team used three hosted models, one analytics SDK and a community vector host. Nobody maintained a register. The DPA negotiation starts from ignorance.

Enterprise Connectors

CRM, ITSM and IdP adapters need rate limits, sandbox tenants and contract tests. Connectors are where tenancy and least privilege meet someone else's API.

The Engineering Problem

The agent writes to production Jira with a personal admin token from a champion. Rate limits are unknown. There is no sandbox project. A bad tool loop opens 400 tickets and pages the customer's on-call. The model "worked".

Key Idea
  • Every connector has a contract: auth, tenant scope, idempotency keys, rate limit, sandbox mode and a fake for Tier L tests.
  • Contract tests run in CI against fakes; periodic contract probes run against sandbox only.

The Engineering Problem

Unit tests check the happy path for tenant A. Nobody ever asks for tenant B's id with A's token, or swaps tid in a tool argument, or fuzzes Unicode tenant strings. The first cross-tenant read is discovered by a customer.

Red-team connectors
  • Attempt production project ids via sandbox credentials.
  • Replay idempotency keys across tenants.
  • Inject prompt text that asks the agent to "use admin token" — harness must still use scoped credentials (Volumes 16–17).

Tenancy fuzzing ideas

  • Empty, whitespace, path traversal and very long tid strings.

  • Concurrent requests alternating tenants on one worker — ContextVar must not leak.

Important Architecture

Failure Modes

  • SSO for humans, god-mode service account for agents.
  • Tenant id only in the prompt.
  • Residency claimed while logs export globally.
  • Public model endpoints behind a "private" app subnet.
  • Mutable prompt logs without redaction policy.
  • Certification claims without evidence artefacts.
  • Undocumented subprocessors and training-use clauses.
  • Production connectors without sandbox or rate limits.
  • Hotfix prompts without digests or rollback.
  • Happy-path tests only — no cross-tenant probes.

Evaluation

  • OIDC validator rejects unknown roles and missing tid.
  • Tenancy middleware raises without context; filters never leak.
  • Residency policy denies cross-region planes for pinned tenants.
  • Audit chain verifies; tampering fails verification.
  • ACL suite all PASS including argument-swap probe.
  • Connector sandbox refuses production projects; idempotency holds.
  • Change promotion requires eval + CAB; rollback cites prior digest.
